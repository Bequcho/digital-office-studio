# Static build sources and regression checks

`python tools/build.py` owns the root fallback, three homepages, 24 profession
pages, 404, SVG sprite and manifest. It discovers sitemap entries from all
indexable HTML, preserving the other generators' pages, robots rules and CRM.
It does not run historical installation workflows or publish anything.

## Source ownership

- `build.py`: page composition, shared header/footer, core profession layout,
  sprite paths, manifest and asset versions.
- `content.json`: shared localized copy and the original core sections.
- `industries.json`: profession identities, visible hero headlines/intros,
  concept image data and core features.
- `home_sections.json`: current prices/currencies and localized audit,
  calculator/GEO promo variants, industry cards, hero stylesheet versions and Clutch content.
  `industries.additionalCards` belongs only to the three public homepages; the
  root fallback keeps its historic card inventory.
- `industry_sections.json`: localized editorial data for profession details,
  pricing and FAQ; each profession declares section placement and whether its
  details replace or supplement the original generic sections.
- `build_components.py`: shared rendering for these sections (not page copies).
- `templates/home-hero-*.html`: existing hero text/layout components.
- `templates/home-media-*.html`: approved hero illustrations and orbit markup,
  composed only into public homepages, not the historic root fallback.
- `templates/home-work-*.html`: approved localized project galleries. These
  section sources replace the obsolete case + portfolio-teaser composition on
  public homepages. They are read directly; builds never extract from output HTML.
- `templates/home-audit-style.html`: the existing inline audit-strip stylesheet,
  moved into a shared source without changing its rendered bytes.
- `seo_metadata.json`, `seo_hreflang.py`, `seo_schema.py`, `seo_social.py`:
  existing centralized SEO generation; visible content does not override them.

The root is a technical English redirect, generated by `root_redirect()`.
It always targets `/en/`, preserving query/hash with JavaScript, and has an
immediate meta-refresh plus a plain link as fallbacks. It never reads browser
language, geolocation, cookies or storage. Canonical/social metadata point to
English; reciprocal hreflang and English x-default remain unchanged. No homepage
scripts run at `/`, so the first logo cycle starts at the destination. The
manifest declares English while keeping its existing root start URL and scope.
Direct language URLs and manual selection are not redirected. The 404 metadata
and asset cache versions remain unchanged. `test_default_language.py` checks
preferences, query/hash, no-JS, unavailable storage and manual language navigation.

The initial synchronization baseline is commit `f2841a62`. Later approved
content changes should update the source and generated HTML together. Do not
use one-off scripts that patch output HTML as the permanent source of content.

## Verification

Run `python tools/test_build.py` and `git diff --check` before accepting a build.
The regression suite:

1. Copies the current checkout into a temporary directory, without `.git`.
2. Deletes all HTML/assets owned by the generator, so skipping generation or
   copying existing output cannot pass.
3. Rebuilds and compares every file byte-for-byte with the approved checkout,
   including non-generated pages, styles, images, robots, sitemap and CRM.
4. Builds again and checks idempotence.
5. Checks prices/currencies, lead scripts/styles, section inventory, home tools,
   portfolio, lawyer sections and root redirect explicitly.
6. Runs the existing metadata/language/hreflang, schema, sitemap and social tests
   against the rebuilt copy.

No network access, git writes, publishing, CRM operations or form submissions
are part of the test. Tests use Python's standard library and do not modify
application files in the working checkout. For an intentional content change,
review and update generated output rather than weakening the comparison.

This repair does not change the separate audit-localization, audit-entry or
IndexNow workflows. Their previously identified issues remain separate work.

## Reference-derived BEQSON contour motion

The three public homepage headers use the original `assets/beqson-mark-v3.png`
as the unchanged base symbol. `assets/brand/beqson-wordmark.webp` is a lossless
RGBA derivative of the owner's photographic wordmark: no font replacement or
redrawing. `prepare_brand_reference.transparent_wordmark` preserves opaque letter
cores and removes the old dark matte with a background model and boundary colour
unmixing. It does not blur/resample the letters. The original opaque crop is
retained in `tools/fixtures/brand-wordmark-source.webp` for strict comparison.
The transparent result uses the same dimensions, spacing and crop coordinates.
Hidden text supplies accessible naming.
The homepage header reserves a horizontal logo layout before JavaScript runs:
the symbol is left of the unchanged photographic wordmark. Its text width is
132 px on desktop, 108 px on mobile and 94 px below 360 px (about 12–15% larger).
Header content heights are 82/72 px, plus the existing 1 px border. Narrow mobile
flag targets keep their 44 px height and use 40/36/32 px widths to fit the logo.
The existing disclosure menu is used below 1280 px only in these homepage
headers; `script.js` uses the matching media query for focus/resize handling.
Other headers keep their existing 1180 px breakpoint. At 1181–1399 px (and all
Georgian desktop widths with the full menu) the existing compact
consultation-label treatment and tighter navigation gaps keep labels within
the header; contact icons and the lead form remain available. All rules are
scoped to the homepage brand header; other headers and hero artwork are independent.

`assets/brand/beqson-contours.json` contains three SVG light fields for each of
146 decoded reference frames at 30 fps. They are registered to the original
PNG's alpha bounds, then clipped by that PNG in the runtime SVG mask. Background
stars/particles are excluded. Only the SVG light paths update; neither bitmap
moves, fades or glows. Symbol and wordmark use independent compositing layers to
prevent browser filter rounding affecting the wordmark's rendered pixels.
Each 4.8667-second pass fades its light at the end, clears all light paths, and
repeats after a 3-second static pause. The light filters apply a 1.2 alpha gain to the moving fields
only; path data, blur radii, duration and the original PNG remain unchanged.
No storage flag suppresses animation on later visits or language transitions.
The light data is fetched once per document. There are no animation frames in
the 3-second pause; hidden tabs and pagehide cancel both frame and timeout jobs,
preserving the remaining pass/pause time for resume. Reduced motion clears the
light and all jobs immediately; disabling it starts a new pass. Missing JavaScript
or light data retain fully visible static artwork. Unavailable storage does not
affect animation. No video, GIF or animation library ships at runtime.

`tools/prepare_brand_reference.py` prepares the lossless assets offline. Supply
`--photo`, `--video` and `--frames` (all 146 `frame-*.png` files decoded by full
FFmpeg without frame dropping). It verifies owner-reference SHA-256 checksums.
The regular build consumes prepared assets and does not require the external
owner files or FFmpeg. `build.py` owns markup and cache versions. Never modify
`logo.svg` to approximate the approved symbol.

Run `tools/test_signature_motion.py` in the existing Playwright environment.
The current contract requires both bitmaps visible at nine widths (320 through
1920 px), exact pixel equality of the wordmark through the cycle, stable bounds,
replay on later visits, no-JS/reduced-motion/failed-data fallbacks, storage independence,
transparent background and exact preservation of opaque photographic letter cores.
The pixel baseline is captured after fonts/images and two paint frames are ready,
before releasing the light-data request; initial browser image rasterization is
kept separate from the animation. Original symbol and contour-data hashes are locked.
Set `BEQSON_SIGNATURE_OUTPUT` outside the repository
to record real-time mobile/desktop videos. The former wordmark-reveal and
320-px hidden-symbol expectations were replaced by the owner's new requirements.
